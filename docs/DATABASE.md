# Database Schema

Target: **PostgreSQL 15+ (Supabase-ready)** — plain SQL, no ORM.

```
server/migrations/001_init.sql   -- schema
server/migrations/002_seed.sql   -- demo data
```

```bash
cd server
npm run migrate    # applies every migration in order (idempotent)
npm run seed       # optional demo data
```

All timestamps are `TIMESTAMPTZ`. Enums are expressed as `VARCHAR + CHECK` so adding a value never needs an `ALTER TYPE`.

---

## Entity map

```
flats 1─n users 1─n visitor_passes 1─n visitor_logs
       │            │
       │            ├─n complaints 1─n complaint_updates
       │            ├─n bookings  n─1 amenity_slots n─1 amenities
       │            ├─n marketplace_listings 1─n listing_enquiries
       │            ├─n events  n─n event_registrations
       │            ├─n device_tokens
       │            └─n notifications (NULL user_id = broadcast)
       │
       └── announcements (author_id → users)
otp_codes (standalone, keyed by phone)
```

---

## Tables

### `flats`
`id UUID PK` · `block` · `flat_number` · `floor` · `bhk` · `is_occupied` · `created_at`
`UNIQUE (block, flat_number)`

### `users`
`id UUID PK` · `phone UNIQUE` · `full_name` · `email` · `role CHECK (resident|security|admin)` · `flat_id → flats ON DELETE SET NULL` · `avatar_url` · `is_active` · `joined_on` · timestamps
Indexes: `role`, `flat_id`. The `updated_at` trigger is applied automatically.

### `otp_codes`
`phone` · `code` · `purpose CHECK (login|visitor_approval)` · `attempts` · `expires_at` · `consumed_at`
Index: `(phone, purpose, created_at DESC)`. Codes are stored **SHA-256 hashed and salted with the phone number**; a code is single-use and expires.

### `device_tokens`
`user_id → users CASCADE` · `token` · `platform` · `last_seen_at` · `UNIQUE(user_id, token)`

### `visitor_passes`
`id UUID PK` · `host_id → users` · `visitor_name` · `visitor_phone` · `visitor_count` · `purpose` · `vehicle_number`
`pass_type CHECK (preapproved|walkin|delivery)` · `delivery_vendor`
`qr_token UUID UNIQUE` · `otp_code VARCHAR(6)` · `status CHECK (pending|approved|rejected|checked_in|checked_out|expired)`
`valid_from` / `valid_until` (default +12 h) · `approved_by` · `verified_by` · `entry_at` · `exit_at` · `remarks` · timestamps
Indexes: `(host_id, created_at DESC)`, `(status, created_at DESC)`.

### `visitor_logs` (audit trail)
`visitor_id → visitor_passes CASCADE` · `action CHECK (requested|approved|rejected|entry|exit|denied|otp_verified|qr_verified)` · `performed_by` · `performer_role` · `remarks` · `created_at`
Index: `(visitor_id, created_at DESC)`.

### `complaint_categories`
`id SERIAL PK` · `name UNIQUE` · `icon` · `description` · `is_active`

### `complaints`
`id UUID PK` · `reference_no UNIQUE` (built from `complaint_ref_seq`, e.g. `CC-20261008-0007`)
`raised_by → users` · `category_id → complaint_categories` · `title` · `description` · `image_url`
`priority CHECK (low|medium|high)` · `status CHECK (submitted|in_progress|resolved)`
`assigned_to` · `resolution_note` · `created_at` / `updated_at` / `resolved_at`
Indexes: `(raised_by, created_at DESC)`, `(status, created_at DESC)`.

### `complaint_updates`
`complaint_id → complaints CASCADE` · `from_status` · `to_status` · `note` · `actor_id` · `created_at`
One row per status transition; powers the timeline shown in the app.

### `amenities`
`id SERIAL PK` · `name UNIQUE` · `description` · `icon` · `location` · `capacity`
`open_time` (06:00) · `close_time` (22:00) · `slot_minutes` (60) · `advance_days` (7) · `is_active`

### `amenity_slots`
`id BIGSERIAL PK` · `amenity_id → amenities CASCADE` · `slot_date DATE` · `start_time` · `end_time`
`is_blocked` · `blocked_reason` · `UNIQUE (amenity_id, slot_date, start_time)` · `CHECK (end_time > start_time)`
Index: `(amenity_id, slot_date)`. Slots are generated by the admin in date ranges (≤ 62 days).

### `bookings`
`id UUID PK` · `slot_id → amenity_slots` · `amenity_id → amenities` · `user_id → users`
`attendees` · `notes` · `status CHECK (confirmed|cancelled)` · `booked_at` · `cancelled_at` · `cancelled_by`

```sql
CREATE UNIQUE INDEX uq_booking_slot ON bookings(slot_id) WHERE status = 'confirmed';
```
A **partial unique index** makes double-booking impossible at the database level.

### `marketplace_listings`
`id UUID PK` · `seller_id → users CASCADE` · `category CHECK (homemade_food|jewellery|used_products|tuition|yoga_fitness|other)`
`title` · `description` · `price NUMERIC(10,2)` · `price_unit` · `image_url` · `contact_phone`
`status CHECK (pending|approved|rejected|sold|inactive)` · `rejection_reason` · `approved_by` · `views` · timestamps
Indexes: `(status, created_at DESC)`, `(status, category)`.

### `listing_enquiries`
`listing_id → marketplace_listings CASCADE` · `buyer_id → users CASCADE` · `message` · `is_read`

### `announcements`
`author_id` · `title` · `body` · `category CHECK (general|maintenance|security|event|emergency)`
`image_url` · `is_pinned` · `audience CHECK (all|resident|security|admin)` · `published_at`
Index: `(published_at DESC)` — feed ordering is *pinned first, then newest*.

### `events`
`author_id` · `title` · `description` · `venue` · `starts_at` · `ends_at` · `image_url`
`capacity` · `registration_deadline` · `status CHECK (draft|published|cancelled|completed)`

### `event_registrations`
`event_id → events CASCADE` · `user_id → users CASCADE` · `status CHECK (registered|cancelled)` · `UNIQUE (event_id, user_id)`

### `notifications`
`user_id → users CASCADE` (**NULL = broadcast to everyone**)
`type CHECK (visitor|complaint|booking|announcement|event|marketplace|system)`
`title` · `body` · `data JSONB` · `read_at` · `created_at`
Index: `(user_id, created_at DESC)`.

## Triggers

`set_updated_at()` fires `BEFORE UPDATE` on `users`, `visitor_passes`, `complaints`, `marketplace_listings`.

## Seed data (`002_seed.sql`)

| Seed | Contents |
| --- | --- |
| Flats | Blocks A/B, sample flats (`A-1201` … `B-402`) |
| Users | 5 accounts on phones `9000000001`–`9000000005` (admin, security, 3 residents), all password `123456` in dev |
| Complaint categories | Plumbing, Electrical, Housekeeping, Lift, Security, Pest control, Other |
| Amenities | Clubhouse, Swimming pool, Gym, Banquet hall, Party lawn, Co-working room (with open/close times and slot length) |
| Slots | 14 days of slots for every amenity |
| Announcements | Sample notices across categories (one pinned, one emergency) |
| Events | 3 upcoming events with capacities |
| Marketplace | 4 approved listings across categories |

Seeding is idempotent (`ON CONFLICT DO NOTHING` / guarded inserts) so it is safe to re-run.
